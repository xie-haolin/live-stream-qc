# 直播内容智能质检 AI 应用（Dify 工作流）

> 输入直播转写稿，自动完成车系识别、违规话术判定（0–4 分级）与屏蔽词过滤，输出结构化质检报告。

---

## 工作流架构

```
开始 → 切句分块（代码）→ 迭代_逐块分析（LLM，并发3，失败隔离）
→ 屏蔽词过滤（代码）→ 合并归一化（代码）→ 结束（结构化报告）
```

| 节点      | 类型                | 职责                                            |
| ------- | ----------------- | --------------------------------------------- |
| 开始      | 输入                | 接收直播转写稿（口播/字幕文本）                              |
| 切句分块    | 代码                | 长稿切成 1000 字/块、重叠 80 字，缩短单块上下文 → 模型更准、token 更省 |
| 迭代_逐块分析 | LLM（迭代，并发 3，失败隔离） | 逐块抽取车系 + 判定违规 0–4 分（`temperature=0`，结果可复现）    |
| 屏蔽词过滤   | 代码                | 子串/正则匹配品牌屏蔽词，确定性执行，零 LLM 调用                   |
| 合并归一化   | 代码                | 车系别名归一化去重 + 违规分档计数 + 屏蔽词命中汇总                  |
| 结束      | 输出                | 返回结构化质检报告（车系清单 / 违规统计 / 屏蔽词命中 / JSON）         |

---

## 核心设计决策

1. **LLM 与代码职责分离**
   LLM 只做「理解/识别」这类不确定性任务（车系抽取、违规分级）；去重、归一化、屏蔽词等确定性工作全部交给代码。这是降本的关键——能用词库/正则解决的，绝不调 LLM。

2. **批量处理用并发迭代 + 失败隔离**
   迭代节点开启 `is_parallel`、并发数为 3；失败处理模式设为 `remove-abnormal-output`，单块异常被隔离丢弃，不拖垮整批。

3. **判定类 `temperature=0`**
   违规分级属于判定任务，固定 `temperature=0` 保证结果可复现、可横向对比，审核结论不因随机性漂移。

---

## 效果数据（原型测算）

| 指标       | 结果             | 口径                                  |
| -------- | -------------- | ----------------------------------- |
| LLM 调用次数 | **↓ 约 50%**    | 屏蔽词过滤、车系归一化等确定性后处理由代码替代，省去对应 LLM 调用 |
| 吞吐       | **较串行 ↑ 约 6x** | 迭代并发 3，理论提速约 `并发数 × (1 − 串行占比)`     |

> 以上为基于原型架构的**测算值**（代码后处理替代 LLM 调用 + 并发迭代的理论收益），非生产实测。落地业务环境后应使用真实数据重测并替换该口径。
